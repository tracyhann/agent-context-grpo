The Credibility Baseline

The step baseline is a read from an episodic return memory: key = state, value = a sibling rollout's return, read = their mean. A plain mean is invariant to how much evidence backs it — one sibling reads as confidently as forty. This arm restores that information by shrinking each state's baseline toward the task prior in proportion to its support: λ = J/(J+κ).

01 — the framing

An episodic return memory, not a critic

Write the step baseline as a memory read and the whole method reads differently — and the defect becomes obvious.

M
memory = { (k_j, v_j) }, k_j = state of turn j, v_j = that rollout's return from j
Keys are states in this batch; values are real Monte-Carlo returns, not predictions.
R
V̂(s_i) = Σ_j w_ij v_j / Σ_j w_ij, w_ij = 1 if same state and different rollout, else 0
Under the hard gate the kernel is an indicator, so the read is a plain mean over the other rollouts at that state. A = G − V̂(s).
!
Σw cancels ⇒ the read cannot tell 1 neighbour from 40
The defect. Normalisation destroys support density. A state visited once by one sibling produces a baseline as authoritative as one visited forty times — and 17% of turns have three or fewer supporting rollouts.
→
b = λ·V̂(s) + (1−λ)·b_task, λ = J/(J+κ), κ = 2
Credibility (Bühlmann) shrinkage: trust recollection in proportion to the evidence behind it, otherwise fall back on the prior. b_task is the leave-own-trajectory-out task mean; J is the number of distinct other rollouts at the state.
Why this is not a critic in disguise

A parametric critic stores value in weights and predicts it. This stores actual returns and retrieves them by state identity; nothing is learned or bootstrapped. The nearest published relative is Neural Episodic Control (Pritzel et al., 2017), which reads value from a differentiable dictionary of embeddings and returns. PPO with a learned critic is in the same published table as our comparators, at 54.4.

Only 15% of return variance within a task is explained by which state you are in. Shrinkage attacks the 31% estimation noise; better keys could at most reach the 15%. Neither touches the 85% that lives in what happens after the turn.

rejectedtested, null

A turn-matched prior

Since the target depends on turns remaining, a prior matched on turn number looked principled. On the dump that records turn index it is worse on the turns that need it most (dead-row error 7.59 → 8.14) and only 1.7% better elsewhere. Not adopted; the arm keeps one change.

Leakage: the baseline must not see the action it prices

A policy-gradient baseline must be a function of the state, not of the action or its future. Checked line by line: φ is the frozen reference model's hidden state at the last prompt token; the context features count observations up to and including the current one; the node key is the pre-action observation; b_task, J and λ are built from other trajectories only. Masking the own trajectory is necessary but not sufficient, and the representation clears the same bar.

Step 1 matches the control to four decimals — same seed, same games, same base weights, and an estimator that only changes the update. Mean λ ≈ 0.72 says a typical state keeps ~72% of its own evidence and borrows ~28% from the task prior, i.e. a typical J of about 5. The batch's own κ estimate (2.3–3.9) runs above the fixed 2, suggesting the data would accept more shrinkage than we chose; κ stays at 2 as pre-registered, and the estimate is logged every step as the input to a later decision.
What this arm cannot fix

Replayed held-out failures are exploration failures: the agent cycles between two or three receptacles and never opens the cabinet holding the object, because the prompt carries only the last two turns. When every sibling rollout loops and fails, all returns are 0 and there is no step signal to improve — no baseline change reaches that case. Credit-side work is bounded by the 15% ceiling in §02; the exploration work is a separate line (coverage hints, revisit penalties), to be tested on replays before it costs a training run.
