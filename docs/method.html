01 — the one axis that separates these methods

Everything differs on the grouping key

A group-relative policy gradient replaces a learned critic with a baseline computed from a set of comparable experiences. The entire design question is which experiences count as comparable — every method below is a different answer to that, and nothing else about them differs much.

GRPOarXiv:2402.03300
x₀  →  group
Same task. One flat group per prompt; no notion of a step.
GiGPOarXiv:2505.10978
s_t  →  group
Same current state, matched exactly. Anchor states bucket steps inside the rollout group.
HGPOarXiv:2602.22817
(s_{t−k}, …, s_t)  →  group
Same exact k-step history, at every depth at once: each step joins K+1 groups (k=0…K) and their advantages are combined with adaptive weights w_k. Already a weighted blend over grouping granularities — the nearest prior work to a soft neighbourhood. Support still decays fast in k, because each level demands an exact suffix match.
G²POarXiv:2606.22995
o_t  →  graph node
Same observation. Occurrences become nodes in an observation-transition graph.
Oursthis note
(o_t, c_t)  —f_φ→  z_t  →  soft neighbourhood over the whole task
No identity test at all. Every occurrence in the task is a candidate, weighted exp(−d/τ). As τ→0 this tends to an exact-match gate like GiGPO's and G²PO's — though on φ, which is stricter than their observation identity. GRPO and HGPO are not limits of it: GRPO has no step term, and HGPO already blends several exact gates.

The first three prescribe equivalence by identity; HGPO blends several such tests at different depths; the fifth replaces the test itself with a kernel. Revised 2026-09-07: earlier versions of this page said ours "still requires o_u = o_v as a hard gate — it only ever splits a G²PO bucket, never merges across observations." That is no longer true. The shipped gate is global: the whole task is one bucket and the affinity does the gating, so it both splits and merges. Membership becomes continuous rather than binary, which is what stops ~35% of occurrences falling out of the estimator for want of an exact string match.

02b — one training step, end to end

The pipeline

What happens in each of the 100 steps of a run — rollout on the left rail, then credit assignment forking into the episode-level and step-level estimators that sum into the PPO update.

1

Sample tasks & replicate into groups

Draw 16 ALFWorld games from the official train split; replicate each ×8 (same game, same start) → 128 concurrent episodes. The 8 siblings of a task are the comparison group — no critic anywhere.

2

Multi-turn rollout (≤50 turns each)

Per turn: prompt = task + last-2 history + observation + admissible actions → policy generates ≤512 tokens of <think>…</think><action>…</action> (the CoT itself is trained) → parser extracts the action → env returns reward (success 10 / invalid −0.1). Generation runs on vLLM 0.11.0 with VLLM_ATTENTION_BACKEND=TRITON_ATTN (Blackwell sm_120); the trainer uses flash-attn 2.8.3 with use_remove_padding=True. Sampling matches the reference: rollout temp 1.0, top-p 1.0, top-k unrestricted; validation temp 0.4 with do_sample=True. Measured 190 s of the 406 s step.

3

Flatten to occurrences

Episodes break into ≈6,000 transitions u=(trajectory i, turn t), each carrying its observation text, its position in the trajectory, and its discounted return-to-go (γ=0.95).

4
episode level — shared with GRPO

AEP: group-relative return

Episode return standardised against the 7 siblings (mean_std_norm) and broadcast to the trajectory's tokens. This half is identical in the GRPO baseline arm.

step level — ours (ccpo)

ACC: context-conditioned step credit

Gate: global — the whole task is one bucket; no identity test. G²PO's node is the τ→0 limit.
Target: G²PO's successor node value V(next(u)), pooled over every sibling that visited that successor — not the return-to-go.
Context: φ = whitened reference-policy hidden state ‖ thermometer-coded {t, n_unique, revisit, progress}.
Baseline: leave-one-out over other trajectories, weighted exp(−d(φ)/τ_b), τ_b = 0.15 × median, aggregated per trajectory before across.
Edge: G²PO's V(next) − V(current), standardised per task, added on.
Trust: λ = 1 — bypassed under the global gate, since b_obs there is the uniform task mean and measures worse than the exact gate.

Same screen, different history: at "You open the microwave 1…", the rollout that arrived at t=5 carrying the apple is not judged by the one that wandered in at t=23 empty-handed — its weight decays with context distance. Measured outcome: the mechanism runs (effect_rel 0.119 against exactly 0.000 before), and an ON/OFF ablation puts its contribution at −0.01 points over nine evaluations.
5

Combine & normalise

A = AEP + w·std-norm(ACC) with w=1; the step term is standardised per task so equal weight means equal scale (the family's mean_std_norm convention). Buckets with identical contexts collapse to the plain G²PO baseline by construction.

6

Token-level PPO update

~25 minibatches of 240 transitions: PPO clip on every response token, KL-to-reference penalty 0.01 with the log-ratio clamped to ±20 before exp (the NaN fix), grad-clip 1.0, lr 1e-6. FSDP updates the weights — and the same module generates the next step's rollouts (no engine, no weight sync).

7

Evaluate & checkpoint

Every 5 steps: 128 episodes on ALFWorld unseen (temp 0.4). Every 25 steps: checkpoint to results/verl_ccpo_alfworld/. Curves land in fig_verl_curves.png; the estimator's health prints every step as [ccpo] λ_u · n_eff · live · buckets.

⊕ where uncertainty lives in the method — click to expand

Status, 2026-09-07. This dial was designed as the method's second idea, alongside context-conditioned grouping. It is not in the shipped path. Under the global gate λ is forced to 1; on the hard-gate path the rule runs and returns λ = 0.011. Everything below describes the intended mechanism and remains the design; read it as such, not as a description of what produced the 79.7% result.

Step 4 — the λ trust dial was intended as the method's single, load-bearing uncertainty mechanism: before the context-weighted baseline is used, λ asks "how uncertain is this conditioned estimate relative to the bias it removes?" and blends accordingly. revisedThe shipped rule is hierarchical empirical Bayes, not the MSE form previously shown here:

τ² = max(0, E[d²] − E[Var(d)]),   d = ρ(b_obs − b_LOO)
λ_i = τ² / ( τ² + ρ²σ²(1/n_eff − 1/J) )

τ² is estimated once over the whole batch — thousands of occurrences — where the statistical power is; the shrinkage is then per occurrence against its own noise. The superseded MSE form (ρB)²/((ρB)² + σ²(1/n_eff − 1/J)) is kept behind ACG_CCPO_SHRINK=mse and fails for a specific reason: writing the bias prior B in sd units makes σ² cancel, so it reduces to 0.09/(0.09 + var_gain) — a pure function of n_eff and J, i.e. exactly the n_eff rule it was written to replace (measured corr(λ,|d|) = −0.239).

Each symbol carries one species of uncertainty:

  • σ² — outcome uncertainty: within-bucket variance of the other trajectories' returns. Noisy neighbors → shakier conditioned baseline → λ shrinks.
  • n_eff — effective-sample uncertainty: weight concentration reduces how many neighbors you're really averaging (n_eff = (Σw)²/Σw²); 1/n_eff − 1/J is precisely the extra variance purchased by conditioning versus using the whole bucket. Measured: n_eff 5.84 under the global gate (bucket = task) against 4.93 under the hard gate — the soft kernel buys more effective neighbours, not fewer.
  • ρ — metric uncertainty: confidence that φ-distances mean anything. An uninformative metric can't deliver the bias reduction, so ρ→0 collapses λ→0 (back to G²PO) no matter how the numbers look.
  • τ² — signal variance: how far the conditioned baseline moves from the uniform one beyond sampling noise, pooled over the batch. This replaces the fixed bias prior B (0.30 sd), which was measured on the retired Qwen3 setup and is no longer used. Measured now: τ² ≈ 0 — hence λ = 0.011.

So uncertainty isn't modeled as an explicit posterior — it's an empirical-Bayes arbitration: trust conditioning exactly in proportion to how much of the observed disagreement survives its own noise. One supporting appearance elsewhere: τ_b (0.15 × median bandwidth) normalises distance-scale uncertainty away. The entropy floor on the probe (§02's H(q) ≥ H_min) belongs to the successor-feature MVP in ccpo/learned.py, which nothing imports — it is not a stabiliser in the shipped path because that path has no probe.

What the measurement says. A controlled ablation — context conditioning fully ON (λ=1, effect_rel 0.119) versus fully OFF (λ=0.011, effect_rel 0.001), with target, edge term, prompt and seed identical — returns a mean difference of −0.01 points over nine evaluations, 95% CI [−2.8, +2.8]. The dial is not merely bypassed; on this benchmark there is nothing for it to arbitrate.

Project history: richer uncertainty machinery — evidential deep learning for the affinity, learned variance heads — was built and considered during the learned-components phase, and dropped when the whole learned stack failed to beat the frozen φ. The conclusion (recorded in idea.md): uncertainty belongs in the estimator arithmetic (λ*), not in a trained module that would itself need calibrating.

What the five together say

Examples 1, 3 and 4 are the mechanism doing exactly what it was designed to do: pooling genuine twins, splitting an observation match that shares no situation, and merging across a one-token difference the hard gate would have discarded.

Examples 2 and 5 are why it does not translate into performance. In 2 the discriminating information does not exist yet at the moment φ is computed; in 5 there is nothing to discriminate. Together they are the qualitative face of H-H's measurement — only ~12% of within-bucket return variance is attributable to how a trajectory arrived, because on ALFWorld what happens next is dominated by the action chosen now.

02d — the shipped estimator, 2026-09-06

What actually runs, and what is only an option

§02's five equations describe the successor-feature MVP: a frozen μ̃ψ probed under an entropy floor (Eq. 2) and a distributional distance over a shared action set (Eq. 3). None of that is in the shipped estimator. It lives in ccpo/learned.py, which nothing imports. What ccpo/core_ccpo.py runs is the frozen rung: φ is either the reference policy's whitened last-prompt-token hidden state or a hashed bag-of-words, and the affinity is exp(−d/τb) on that. Eq. 1, 4 and 5 are faithful; Eq. 2 and 3 are the plan, not the code, and the §05 cost model built on probe scoring prices a method that was never the one evaluated.

Eq. 5 and the λ* dial in §02c still show the MSE shrinkage rule. The shipped default is the positive-part empirical-Bayes rule λ* = max(0, 1 − Var(d)/(ρd)²) on the realised disagreement; the MSE form is kept behind ACG_CCPO_SHRINK=mse and is superseded because, with the bias prior written in sd units, σ² cancels and it reduces to the neff rule it was written to replace (corr(λ, |d|) = −0.239). See method-changes.html.

The shipped estimator, as of 2026-09-07 (ccpo-global)

ACC = target − bLOO, where the gate is global: the whole task is one bucket and exp(−d/τ) with τ = 0.15 × median φ-distance decides the neighbourhood softly. The exact-observation gate of GiGPO and G²PO is the τ→0 limit of this, so the two are one mechanism rather than alternatives.

The target is G²PO's successor node value V(next(u)); the baseline is φ-weighted, leave-one-out by trajectory, aggregated per trajectory before across; and G²PO's edge term V(next) − V(current) is added, standardised per task.

λ is forced to 1 and the shrinkage is bypassed. Under a global gate b_obs degenerates to the uniform task mean, which measures worse than the exact-match gate (LOO residual R² 0.425 vs 0.458), so shrinking toward it would actively hurt. The soft kernel is the gate and there is nothing left to shrink toward. The uncertainty half of the method is therefore not exercised in this configuration, and the λ* discussion below describes the hard-gate path only.

Measured effect: effect_rel 0.119 against exactly 0.000 in every prior arm, and live_frac 1.000 — nothing goes uncredited, where the exact gate leaves ~35% of occurrences with no comparable trajectory. The mechanism runs. A controlled ablation says it buys nothing: context conditioning ON versus OFF differs by −0.01 points over nine evaluations.

And λ is not merely failing to detect a shift that exists. λ only sees whether φ moves the mean of the baseline, so a φ that ordered neighbours correctly without moving that mean would read as zero. Measured directly, over the pairs that actually feed the estimator: phi_rel_corr = −0.0096, positive in 42% of buckets against a 50% chance rate. φ-distance does not predict target-distance inside a bucket — not from the policy's hidden state, not from explicit {t, n_unique, revisit, progress}, not from both, not from bag-of-words, and not with the whole episode in the prompt via compaction. Six variants, two targets.

The likely reason is structural rather than a defect in φ. Inside a bucket the observation is identical by construction, so what the target depends on is which action was taken — and φ is the reference policy's prompt hidden state, computed before the response exists. That is correct by design: a baseline must not depend on the action it evaluates. But it means the method needs situation-similarity to predict outcome-similarity, and on ALFWorld what happens next is dominated by the choice made now rather than by how the agent arrived.

Neither escape survives. Support is ample: n_eff 4.86–4.93 of a maximum 7, mean bucket size 8.4, 90% of samples credited, 758 buckets per step — the earlier n_eff ≈ 2.1 figure came from a four-rollout smoke test where J was capped at 3 by construction. And the shrinkage rule is not the cause: eb, eb_pooled and the hierarchical eb_hier independently agree.

What remains once λ=0 is the leave-one-out exclusion (Eq. 1, which E6 supports) and, with ACG_CCPO_TARGET=nextnode, G²PO's successor-value target. Both change the credit substantially — rGiGPO falls to +0.39 — but neither is context conditioning.

A trap worth keeping

In any same-observation grouping study, bucket size and bucket informativeness are anti-correlated. The largest bucket for a task is always the episode-start observation — every rollout shares it, and every occurrence in it has identical context because nothing has happened yet. Ranking candidate states by bucket size therefore selects against the effect you are trying to measure. In our first pass, 50% of pinned states sat at t = 0 and 13 of 24 pairs had no context difference at all.

Scoring the whole action set is cheaper than generating one action

Autoregressive decode is memory-bandwidth-bound: six sequential steps, each re-reading all 1.7B weights. Scoring is compute-bound: encode the shared prompt once, keep the KV cache, then one batched forward over 45 × 6 candidate tokens — two weight reads total, densely batched. Realising the 0.37× needs shared-prefix scoring, which vLLM's OpenAI API does not expose but which is natural inside a verl-style trainer that owns the forward pass.

The caveat that bounds this: it holds only where the environment supplies a discrete admissible set. For open-ended text actions there is nothing to score, generation returns, and the probe becomes a genuine additive cost.

The design error, stated plainly

ACG_CCPO_GATE=global uses context conditioning to replace state grouping: one bucket per task, with φ expected to recover the structure. φ measures inert four independent ways, so in practice each action is scored against a task-wide average.

G²PO scores an action against other actions taken from the same state — the mechanism the entire GiGPO/G²PO family rests on. We swapped a working mechanism for one carrying no signal.

Context conditioning should have refined the state key, not replaced it.

What the state key is missing, measured — 29.1%

G²PO's anchor is observation + admissible-action set. Ours is the observation alone. On 264,058 dumped occurrences from the hard-gate arm (whose key is exactly (task, observation)), the admissible set splits 31.1% of nodes and explains 29.1% of the within-node variance in V(next).

That is five times context conditioning's 6.1% ICC ceiling, and it is the quantity the step term predicts. Pooling states whose available actions differ destroys it.

It also explains why ccpo-hardedge failed while using G²PO's key: the key was right, the anchor feeding it was too coarse.

Latest result: forcing context on top of G²PO's grouping fails. ccpo-refined fixed the design error: context conditioning refines G²PO's partition (hard gate on observation + admissible actions + failure repair) instead of replacing it, with λ forced to 1 so the context term genuinely operates. The test was valid throughout (λ = 1.000, and context carries 17.6% of |A|). It trailed base at 9 of 10 evaluations and failed its step-50 judgement: 36.7% vs 50.0% (−13.3, beyond 2SE), with a pooled −5.8. Its losses concentrate in the clean, cool and heat tasks.

What it showed — context has real structure once the state is right, but too little to act on

On the observation-only partition the between-node variance τ² that context exists to explain was positive on 0 of 130 steps. On the refined partition it is positive on 65%. So the refinement does give context real structure — the shrinkage was partly responding to a bad partition, not only to a bad idea.

But the λ that empirical Bayes would assign, logged throughout, is flat at ~0.04: about 4% of the advantage on context, 96% on the plain node baseline. The structure is real and far too small to matter, so the principled shrink=eb follow-up was cancelled.

HGPO reproduced: its own code, unmodified, reaches 93.0 at 160 iterations (published 92.77). At the matched 100-iteration budget it scores 79.7 (window 85–100: 76.0), which ties our best arm and sits ~14 points behind G²PO. So per iteration, G²PO is the baseline to beat. GiGPO (its own code) reproduces its published 86.7 at 150 iterations exactly, and scores 76.6 at step 100 (window 74.2). At that budget GiGPO, HGPO and our best arm form one cluster within noise, and G²PO sits ~14 points above it. This is not a prompt change. The prompt is built before this block and is untouched. What it rewrites is anchor — which in our tree feeds anchor_obs into the estimator as the state identity used for node grouping. A wrong anchor means occurrences in genuinely different states share a baseline.

(B) — a failed action must not advance the anchor

Without it our anchor becomes the literal string "Nothing happens." on every failed action, so unrelated failed states anywhere in the batch collapse onto one node. With it, a failure at state S carries S's last real observation and joins S's own node.

(C) — invisible-state actions must be carried forward

ALFWorld does not restate the result of heat / cool / clean / turn-on in the next observation, so “egg heated” and “egg not heated” carry identical anchor text. Concatenating the previous observation preserves the distinction.

Honest check that undercuts this half: the obvious test is whether our per-type deficits fall on the four pattern-affected types. They do not — those four average 77.8 against the two unaffected types' 78.6. (B) is untested by that comparison and is the more plausible mechanism.

(A) — the disambiguator we built and never used

G²PO folds the admissible-action list into the anchor, so its node identity is observation text plus admissible actions. Ours is the observation text alone.

This tree already carries that list, as the aff field, added because 42.8% of observations map to more than one admissible set. It is threaded all the way into the estimator — and used at exactly one place, to write a column into a diagnostic CSV. We measured the ambiguity, built the disambiguator, and then grouped without it.

What the retired runs measured

Two generations of matched-scale runs (v5, v6) were done on Qwen3-1.7B with HF-generate and later vLLM sidecars. What carried over

Generation collapse is real and structural. v5 drifted 54 → 478 response tokens with 43% of responses truncated before emitting <action>. Budget forcing (ACG_FORCE_BUDGET) makes truncation-without-action impossible. On Qwen2.5-1.5B-Instruct the collapse does not occur — response length sits at 75–95 tokens across 100 iterations and valid_action_ratio stays ≥ 0.999 — so the guard is retained but inactive.

Revisiting is the long-horizon failure mode — but the digest is not the fix. 58.7% of turns revisit a previously seen observation, and failing trajectories revisit 2.68× as often as successes (10,365 trajectories). A 2-turn window cannot record where the agent has been, and the compaction digest was built to target exactly that. Three arms have now tested it and all three finished below base (see 05b). The diagnosis stands; the remedy does not follow from it. What the digest actually did was lengthen responses at 15 of 15 paired steps and lower KL at 15 of 15 — added cost on both ends, and a suppressed policy update, rather than the promised substitute for re-deriving state.

The revisiting diagnosis may point somewhere else entirely. An agent that cannot tell it has been somewhere before is also an agent whose anchor cannot tell those visits apart — which is the grouping defect identified in 05b-bis, not a prompt-context defect. The same measurement supports both readings; only one of them has survived a training run so far, and it is not this one.

Eval protocol — two corrections

Split — settled. verl maps eval_in_distribution → valid_seen and eval_out_of_distribution → valid_unseen, defaulting to the former. Neither the G²PO nor the GiGPO paper states which it reports — zero occurrences of "seen", "unseen", "in-distribution" or "out-of-distribution" in either — but neither run script overrides the default, so both are on valid_seen. We now match. (The In-Success / Out-Success split comes from HGPO, a separate re-implementation, which is why HGPO reports GiGPO at 90.16 where GiGPO's own paper reports 86.7.) An earlier check found the distinction near-irrelevant here anyway: the same checkpoint scored 0.312 seen against 0.320 unseen.

The evaluation set is not fixed — corrected 2026-09-07. Earlier versions of this page described validation as "128 fixed held-out episodes". That is wrong. ALFWorld's TextWorld backend shuffles the game list per worker seed and iterates: gamefiles = [next(self._gamefiles_iterator) ...], so reset() advances to the next game and every validation scores a different draw of 128 episodes.

The consequence is large and it applies to the baselines too, since this is the reference harness's own behaviour. Measured on our 100-iteration arm, a single evaluation carries ±13 points at 2σ — roughly three times the ±0.048 binomial figure quoted previously, because the task draw varies on top of temperature-0.4 sampling. Step-to-step deltas below ~13 points carry no information, matched-step comparisons between two arms compare different task sets, and only endpoints or many-evaluation means are worth weighing. This is presumably why every baseline paper reports a 3-seed mean; ours is a single draw, and its error bar should be read accordingly.

06 — where it stands

Where the 15 points went

The central hypothesis of this method did not survive contact with ALFWorld. Context-conditioned grouping — the idea the whole page is built around — measures as inert here, four independent ways: the ON/OFF ablation at −0.01 points, phi_rel_corr 0.011 (R² 0.00013), an ICC ceiling of 6.1%, and φ-weighting inside a bucket scoring worse than uniform. The 79.7 that this method reaches came from restoring G²PO's edge term, which we had switched off.

Three further ideas of our own were tried and all three failed. Local σ standardisation (64.1, refuted). Longer training (145 steps, +0.00). The memory digest, in three variants, each below base — and with its stated mechanism refuted by paired measurement rather than merely unsupported.

What made the difference was reading the reference implementation, not theorising. Every explanation for the 15-point gap was eliminated in turn — configuration, evaluation protocol, split, training length, context conditioning, memory, and the estimator itself (r ≈ 0.90 with G²PO's advantage, with our port of their algorithm then verified faithful line by line). What survived was two mechanisms in G²PO's environment manager that this tree never had, both acting on the anchor that defines node identity: failures collapsing onto a single shared anchor, and 42.8% of observations conflated because the admissible-action list we already compute was never put into the key.

Neither is an idea. Both are code that exists in the implementation that produced 95.0 and did not exist in ours. That is a less flattering answer than a new estimator, and a more likely one.

What is not yet known. Whether those two mechanisms close the gap. The arm carrying both (ccpo-anchor-20260909) is running as a single-variable change from the 79.7 arm; step-1 diagnostics confirm the grouping changed as predicted (nodes 758→1172, singletons 0.335→0.291, rollouts identical). Structural improvement has already failed to become accuracy once here — the hard-gate comparison moved effect_rel a hundredfold for −0.01 points — so the arm is judged on held-out success at steps 20 / 50 / 100 against 21.1 / 50.0 / 79.7, and on nothing else.

Standing caveats. Every number on this page is a single seed, including the headline 79.7; the paired between-arm sd is ~5.3 points. Published rows are 3-seed means. And no stepN-best figure should be quoted from this project — best-checkpoint selection is biased upward by roughly 1.5 sd, which on these runs is about 7 points.
